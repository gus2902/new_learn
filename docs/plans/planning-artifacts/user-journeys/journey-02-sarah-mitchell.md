# User Journey: Sarah Mitchell - 첫 사용자의 빈 캔버스 경험

**Persona:**
- **이름**: Sarah Mitchell
- **나이**: 28세
- **직업**: Junior Software Engineer
- **위치**: 샌프란시스코, 미국
- **배경**: 막 커리어를 시작한 엔지니어. PKM 도구를 한 번도 써본 적 없음. 빈 캔버스에 대한 두려움이 큼.

**AARRR 단계**: Activation (First-time User Experience)

---

## Act 1: 빈 캔버스의 공포 (Day 0)

Sarah는 Hacker News에서 Moments 포스트를 봤다.

> "Show HN: Moments – A knowledge manager that organizes itself"

댓글을 읽었다.

**Comment 1**: "Finally, a PKM tool that doesn't overwhelm me!"
**Comment 2**: "No folders, no tags. Just capture and forget."

Sarah는 고민했다.

*"나... 한 번도 이런 거 안 써봤는데. 잘할 수 있을까?"*

예전에 Notion을 시도했었다. 하지만 빈 페이지 앞에서 얼어붙었다.

- "어떤 템플릿을 써야 하지?"
- "폴더 구조를 어떻게 짜지?"
- "태그는 뭘로 하지?"

결국 2주 만에 포기했다.

*"Moments도... 똑같을 거야. 또 실패하면 어떡하지."*

하지만... 댓글이 계속 마음에 걸렸다.

"Just capture and forget."

"한 번만... 시도해볼까?"

---

*"이제 나올 거야. '폴더를 만드세요', '목표를 설정하세요'..."*

하지만...

그냥... 빈 캔버스. 그리고 한 문장.

**"오늘 무엇을 발견했나요?"**

Sarah는 미소 지었다.

*"이거... 부담이 없네."*

## Act 3: 첫 캡처의 마법 (Day 1, 오후)

회사 Slack에서 동료가 공유한 아티클을 봤다.

"Clean Code: 5 Essential Practices for Junior Developers"

Sarah는 읽기 시작했다. 유용했다.

*"나중에 다시 봐야겠는데... 어디에 저장하지?"*

예전 같았으면:
1. Notion 열기
2. "어느 페이지에 넣지?" 고민
3. 새 페이지 만들까 말까 고민
4. "나중에 정리해야지" 스트레스
5. 결국 안 함

하지만 지금은...

공유 버튼 → Moments → **2초**. 끝.

"...이게 끝?"

폴더 선택 없음. 태그 입력 없음. 제목 수정 없음.

그냥... 저장됐다.

Sarah는 Moments 앱을 열었다. 방금 저장한 아티클이 보였다.

깔끔한 카드 형태. 제목, 요약, 이미지.

"와... 이렇게 간단해?"

## Act 5: 첫 일기의 용기 (Day 10)

수요일 밤. 힘든 하루였다. 첫 프로덕션 버그를 만들었다.

집에 돌아와 침대에 누웠다. 스마트폰 알림.

**💭 Moments: "오늘은 어땠나요?"**

Sarah는 고민했다.

*"일기... 나 일기 써본 적 없는데. 뭘 써야 하지?"*

하지만... 오늘은 정말 힘들었다. 누군가에게 말하고 싶었다.

앱을 열었다. 일기 화면.

*"일기 쓰려면... 완벽한 문장을 써야 하는 거 아니야?"*

하지만 화면에는 그냥 빈 페이지만 있었다. 어떤 형식도, 템플릿도 없었다.

Sarah는... 그냥 타이핑했다.

> "오늘 첫 프로덕션 버그를 만들었다. 진짜 죄송했다. 선임한테 혼날 줄 알았는데, 오히려 '괜찮아, 다들 처음엔 그래'라고 해줬다.
>
> 고마웠다."

저장 버튼을 눌렀다.

화면에 부드러운 애니메이션이 나타났다.

**✨ "첫 일기가 저장되었습니다."**

그리고 하단에...

**"오늘 저장한 클립 1개가 이 일기와 연결되었습니다."**

Sarah는 클릭했다.

"Debugging Like a Detective" (Day 5에 저장)

*"아... 내가 무의식적으로 버그 고치는 법을 찾고 있었구나."*

## Act 6: 재발견의 순간 (Day 21, 3주 후)

3주가 지났다. Sarah는 이제 44개 클립을 모았다.

금요일 오후. 팀 회의에서 tech blog 시작하자는 이야기가 나왔다.

**선임**: "누가 첫 포스트 쓸래?"

Sarah는 조용히 있었다. *"나... 글 잘 못 쓰는데."*

회의가 끝나고 자리로 돌아왔다. Moments를 열었다.

검색: "blog"

결과:
- "Why Junior Developers Should Write Technical Blogs" (Day 3)
- "How to Write Your First Tech Post" (2주 전)
- "Beginner's Guide to Technical Writing" (1주 전)

Sarah는 놀랐다.

"나... 블로그에 관심 있었나?"

클립들을 다시 읽었다. 하이라이트한 부분들:

> "The best time to start writing is when you're learning. Beginners have a unique perspective that experts forget."

> "You don't need to be an expert. You just need to share what you learned today."

Sarah는 깨달았다.

**"나... 이미 준비하고 있었어. 무의식적으로."**

다음 주 월요일, Sarah는 손을 들었다.

"제가... 첫 포스트 써볼게요."

## Requirements Revealed

**First-Time User Experience (MVP 필수):**

1. **Minimal Onboarding**
   - "아무것도 준비하지 마세요" 메시지
   - 폴더/태그 설정 건너뛰기
   - 3개 화면 이하로 완료

2. **빈 캔버스 디자인**
   - 홈 화면: 완전히 비어있음
   - "오늘 무엇을 발견했나요?" 한 문장만
   - No 템플릿, No 가이드

3. **첫 캡처 경험**
   - 2초 내 완료
   - 폴더/태그 선택 없음
   - 즉시 보기 좋은 카드 형태로 저장

4. **자동 연결 시각화**
   - "자동으로 연결된 클립 발견됨" 알림
   - 시각적으로 연결 관계 표시
   - "당신이 아무것도 안 해도 우리가 합니다" 느낌

5. **첫 일기 유도**
   - Day 3-10 사이 부드러운 알림
   - 일기 화면: 빈 페이지 (템플릿 없음)
   - "오늘 저장한 클립" 자동 연결
   - "첫 일기" 축하 애니메이션

6. **재발견 경험**
   - 검색 시 관련 클립 그룹화
   - "당신이 이미 준비하고 있었어요" 느낌
   - 과거 클립의 재활용 촉진

**Key Metrics:**
- 첫 캡처까지 시간: < 5분
- 첫 7일 내 캡처 횟수: > 5회
- 첫 일기 작성: Day 3-10 사이
- 첫 3주 리텐션: > 60%

**Emotional Journey:**
- Day 0: 두려움 ("또 실패하면?")
- Day 1: 놀라움 ("이게 끝이야?")
- Day 7: 안도 ("정리 안 해도 되네")
- Day 10: 용기 (첫 일기)
- Day 21: 자신감 ("나 준비돼 있었어")

**입소문 트리거:**
- "온보딩이 3개 화면으로 끝났을 때"
- "자동 연결을 처음 발견했을 때"
- "과거 클립이 지금 필요한 순간에 나타났을 때"
