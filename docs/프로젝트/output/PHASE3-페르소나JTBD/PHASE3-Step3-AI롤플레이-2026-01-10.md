## 👤 페르소나 1: 김지은 (대학원생/연구원)

### 페르소나 세팅 프롬프트

```
당신은 김지은(28세)입니다.
- 직업: 대학원생 (인문학 박사과정 3년차)
- 소득: 월 150만원 (장학금 + 아르바이트)
- 거주지: 서울시 강남구 (원룸)
- 기술 활용 수준: 중상 (Notion, Obsidian 사용 경험 있음)

당신의 상황:
- 논문 작성 중 자료를 찾지 못해 시간을 낭비하는 경우가 많음
- 브라우저 북마크에 500+ 개의 자료가 저장되어 있지만 찾기 어려움
- 수동 태깅/카테고리 설정이 너무 번거로워 정리하지 않음
- 무료 도구를 선호하지만 기능 제한으로 불만

다음 질문에 이 페르소나로서 솔직하게 답변하세요.
```

### 상황별 질문 리스트

1. 논문 작성 중 이전에 본 자료를 찾지 못할 때 어떤 감정을 느끼나요?
2. 자료를 수집한 후 정리하는 과정에서 가장 번거로운 점은 무엇인가요?
3. 브라우저 북마크에 500+ 개의 자료가 있는데, 어떻게 관리하고 있나요?
4. 무료 도구와 유료 도구 중 어떤 것을 선호하나요? 그 이유는?
5. Obsidian을 사용하고 있다고 했는데, 클리핑 도구와 연동이 안되는 것이 불편한가요?
6. 자료를 저장한 후 다시 보는 빈도는 어느 정도인가요?
7. 키워드 검색으로 자료를 찾지 못할 때 어떻게 대처하나요?
8. 논문 주제를 변경했을 때 이전에 수집한 자료 중 관련된 것을 찾는 것이 어려운가요?
9. 하루 중 자료 수집과 정리에 소요되는 시간은 어느 정도인가요?
10. 이상적인 클리핑 도구는 어떤 기능을 가져야 한다고 생각하나요?

### AI 롤플레이 답변 (시뮬레이션)

**질문 1: 논문 작성 중 이전에 본 자료를 찾지 못할 때 어떤 감정을 느끼나요?**

**답변:**
"정말 답답하고 좌절감을 느껴요. 특히 '분명히 좋은 자료였는데...' 라는 생각이 들면서 시간을 낭비했다는 자괴감도 생기죠. 결국 다른 자료로 대체하게 되는데, 원래 찾으려던 자료가 더 적합했을 것 같아서 아쉬움이 남아요."

**질문 2: 자료를 수집한 후 정리하는 과정에서 가장 번거로운 점은 무엇인가요?**

**답변:**
"각 자료마다 태그를 직접 입력하고, 어떤 카테고리로 분류할지 고민하는 게 너무 번거로워요. 하루에 20-30개 자료를 수집하면 정리하는데만 1-2시간이 걸려요. 그래서 결국 '나중에 하자'고 미루다가 그대로 방치하게 되죠."

**질문 3: 브라우저 북마크에 500+ 개의 자료가 있는데, 어떻게 관리하고 있나요?**

**답변:**
"사실 관리가 안 되고 있어요. 북마크를 열어보면 정말 많아서 찾기가 어렵죠. 폴더로 나눠놨지만, 어떤 폴더에 뭐가 있는지 기억이 안 나요. 결국 구글에서 다시 검색하는 경우가 많아요."

**질문 4: 무료 도구와 유료 도구 중 어떤 것을 선호하나요?**

**답변:**
"당연히 무료 도구를 선호하죠. 월 150만원으로 생활하는데 유료 도구에 돈을 쓰기는 부담스러워요. 하지만 무료 도구는 기능이 제한적이라서 불만이 있어요. 그래서 무료 플랜이 넉넉하거나, 학생 할인이 있는 도구를 찾아요."

**질문 5: Obsidian을 사용하고 있다고 했는데, 클리핑 도구와 연동이 안되는 것이 불편한가요?**

**답변:**
"네, 정말 불편해요. 클리핑한 자료를 Obsidian에 옮기려면 수동으로 복사해야 해서 번거로워요. 자동으로 연동되면 좋을 것 같아요. 그래야 워크플로우가 끊기지 않죠."

**질문 6: 자료를 저장한 후 다시 보는 빈도는 어느 정도인가요?**

**답변:**
"솔직히 말하면 거의 안 봐요. 저장할 때는 '나중에 꼭 읽어야지'라고 생각하지만, 막상 다시 찾아보는 경우는 10%도 안 될 것 같아요. 저장하는 순간의 만족감만 느끼고 끝나버리는 거죠."

**질문 7: 키워드 검색으로 자료를 찾지 못할 때 어떻게 대처하나요?**

**답변:**
"정확한 키워드를 모르면 찾기 어려워요. 예를 들어, '인문학 연구 방법론'이라는 주제의 자료를 찾으려고 하는데, 제목에 그 키워드가 없으면 검색이 안 되죠. 그래서 결국 구글에서 다시 검색하거나, 그냥 포기해요."

**질문 8: 논문 주제를 변경했을 때 이전에 수집한 자료 중 관련된 것을 찾는 것이 어려운가요?**

**답변:**
"네, 정말 어려워요. 주제가 바뀌면 관련 키워드도 바뀌는데, 이전에 수집한 자료의 키워드를 기억하지 못하니까 찾기 어려워요. 분명히 관련된 좋은 자료가 있을 텐데 찾지 못해서 아쉬워요."

**질문 9: 하루 중 자료 수집과 정리에 소요되는 시간은 어느 정도인가요?**

**답변:**
"자료 수집은 1-2시간 정도 하고, 정리는... 사실 거의 안 해요. 정리하려고 하면 1-2시간이 더 걸리는데, 그 시간이 아까워서 미루다가 결국 안 하게 되죠. 그래서 자료가 계속 쌓이기만 해요."

**질문 10: 이상적인 클리핑 도구는 어떤 기능을 가져야 한다고 생각하나요?**

**답변:**
"자동으로 태깅하고 카테고리화해주는 기능이 가장 중요해요. 그리고 키워드가 아닌 의미적으로 검색할 수 있는 기능도 필요해요. 그리고 무료 플랜이 넉넉하거나, 학생 할인이 있으면 좋겠어요."

### 답변 분석

**반복되는 키워드:**
- "번거로움", "시간 낭비", "찾지 못함", "정리 안함", "자동화"

**감정 표현:**
- 답답함, 좌절감, 자괴감, 아쉬움, 부담스러움

**우선순위:**
1. 자동 태깅/카테고리링 (가장 높은 우선순위)
2. 의미적 검색 (키워드 검색 한계 해결)
3. 무료/저가 플랜 (가격 민감도 높음)
4. Obsidian 연동 (워크플로우 통합)

### Pain Point 추출 (가장 강력한 불편 요소 3가지)

1. **수동 태깅/카테고리 설정의 번거로움** (심각도: 5/5)
   - 정리 시간 1-2시간 소모
   - 결국 정리 안함으로 이어짐

2. **저장한 자료를 다시 찾지 못함 (Collector's Fallacy)** (심각도: 5/5)
   - 저장 후 재사용률 10% 미만
   - 키워드 검색 한계

3. **무료 도구의 기능 제한** (심각도: 4/5)
   - 가격 민감도 높음
   - 하지만 기능 제한으로 불만

### 상황별 질문 리스트

### AI 롤플레이 답변 (시뮬레이션)

**질문 1: 개발 중 이전에 본 기술 솔루션을 찾지 못할 때 어떤 감정을 느끼나요?**

**답변:**
"정말 답답해요. 특히 '이 솔루션이 정확히 필요한데...' 라는 생각이 들면서 시간을 낭비한다는 스트레스를 받아요. 결국 Stack Overflow나 구글에서 다시 검색하게 되는데, 이미 본 자료를 다시 찾는 게 비효율적이죠."

**질문 2: Readwise Reader를 사용하고 있다고 했는데, 활용률이 낮은 이유는 무엇인가요?**

**답변:**
"클리핑은 하는데, 나중에 찾기가 어려워요. 키워드 검색만 되다 보니 정확한 키워드를 모르면 찾지 못하죠. 그래서 결국 구글에서 다시 검색하게 되고, Readwise는 거의 안 보게 되요."

**질문 3: 키워드 검색으로 관련 자료를 찾지 못할 때 어떻게 대처하나요?**

**답변:**
"의미적으로 검색할 수 있으면 좋을 것 같아요. 예를 들어, 'React 상태 관리'라는 주제의 자료를 찾으려고 하는데, 제목에 그 키워드가 없으면 검색이 안 되죠. 하지만 내용에는 관련이 있을 수 있잖아요. 그래서 의미적 검색이 필요해요."

**질문 4: GitHub, Notion과 클리핑 도구를 연동하고 싶은 이유는 무엇인가요?**

**답변:**
"워크플로우를 통합하고 싶어요. 클리핑한 자료를 Notion 프로젝트 문서에 자동으로 추가하거나, GitHub에 코드 예제를 저장하고 싶어요. 수동으로 복사하는 게 너무 번거로워요."

**질문 5: 기술 자료를 수집한 후 정리하는 과정에서 가장 번거로운 점은 무엇인가요?**

**답변:**
"태깅이 번거로워요. 각 자료마다 태그를 직접 입력해야 하는데, 개발 중에는 그런 시간이 없어요. 자동으로 태깅해주면 좋을 것 같아요."

**질문 6: 코드 예제, API 문서 등 다양한 형식의 자료를 어떻게 관리하고 있나요?**

**답변:**
"GitHub에 저장하거나, Notion에 복사해요. 하지만 클리핑 도구와 통합이 안 되어서 워크플로우가 끊겨요. 통합되면 좋을 것 같아요."

**질문 7: 개발자 커뮤니티에서 추천하는 도구를 신뢰하나요?**

**답변:**
"네, Reddit이나 개발자 커뮤니티에서 추천하는 도구를 많이 신뢰해요. 실제 사용 경험이 있는 사람들의 리뷰가 도움이 되죠."

**질문 8: API를 통한 자동화가 가능한 도구를 선호하나요?**

**답변:**
"당연히 선호해요. 개발자니까 API로 자동화하는 게 편하죠. 예를 들어, 클리핑한 자료를 자동으로 Notion에 추가하거나, GitHub에 저장하는 스크립트를 만들고 싶어요."

**질문 9: 의미적 검색(RAG) 기능이 있다면 사용하고 싶나요?**

**답변:**
"정말 필요해요. 키워드 검색의 한계를 많이 느끼고 있어요. 의미적으로 검색할 수 있으면 훨씬 유용할 것 같아요."

**질문 10: 이상적인 클리핑 도구는 어떤 기능을 가져야 한다고 생각하나요?**

**답변:**
"의미적 검색(RAG)이 가장 중요해요. 그리고 API를 통한 자동화, GitHub/Notion 연동도 필요해요. 그리고 자동 태깅도 있으면 좋겠어요."

### 답변 분석

**반복되는 키워드:**
- "의미적 검색", "API 자동화", "워크플로우 통합", "키워드 검색 한계"

**감정 표현:**
- 답답함, 스트레스, 비효율적, 번거로움

**우선순위:**
1. 의미적 검색 (RAG) (가장 높은 우선순위)
2. API 통합 및 자동화
3. GitHub/Notion 연동
4. 자동 태깅

### Pain Point 추출 (가장 강력한 불편 요소 3가지)

1. **키워드 검색의 한계** (심각도: 5/5)
   - 의미적 검색 필요
   - RAG 검색이 핵심 해결책

2. **도구 간 연동 어려움** (심각도: 4/5)
