# 프로젝트 규칙

## 📋 기본 원칙

이 프로젝트는 **데이터 기반 시장 기회 발굴**을 목표로 합니다. 모든 결정은 데이터와 논리에 근거해야 합니다.

---

## 1. 데이터 우선 (Data First)

### ✅ 반드시 준수해야 할 사항

**1.1 모든 주장에 출처 또는 계산 로직 명시**
- AI가 제시한 통계에는 반드시 출처(URL, 보고서명, 날짜)를 포함
- 추정치는 "약", "대략"과 같은 불확실한 표현 대신 "가정: X, 계산: Y" 형식으로 명시
- 예시: "PKM 시장 규모는 $7.71B (Source: ResearchAndMarkets 2025 Report)"

**1.2 최소 2개 이상의 독립적 소스에서 교차 검증**
- 하나의 출처만 참고하지 말고, 최소 2개 이상의 다른 소스에서 교차 확인
- 예시: 시장 규모를 알 때 ResearchAndMarkets + Gartner 두 소스 확인

**1.3 수치의 논리적 계산 과정 추적 가능하게 작성**
- TAM → SAM → SOM의 계산 로직을 명확히 기술
- 예시:
  ```
  TAM: 대한민국 전체 지식 노동자 1,000만명
  SAM: 그중 IT 종사자 300만명 × 50% (PKM 도구 사용 경험)
  SOM: 150만명 × 5% (초기 시장점유율) = 75,000명
  ```

## 2. AI 활용 (AI Utilization)

### ✅ 반드시 준수해야 할 사항

**2.1 AI에게 "알아서 해줘" 요청 금지**
- 프롬프트에는 반드시 "역할, 목적, 제약, 출력 형식" 4요소 포함
- 예시:
  ```markdown
  역할: 당신은 10년 경력의 시장 분석 전문가입니다.
  목적: PKM 시장의 경쟁 구조를 분석하세요.
  제약: 각 요소를 10줄 이내로 작성하고, 출처를 명시하세요.
  출력 형식: 표 형식
  ```

**2.2 AI 결과를 최소 2회 이상 다른 방식으로 검증**
- 첫 번째 프롬프트로 얻은 결과
- 두 번째 프롬프트: "이 분석의 약점을 3가지 지적하세요" (Devil's Advocate)
- 세 번째 프롬프트: "같은 내용을 다른 각도에서 다시 설명하세요"

**2.3 반복 작업은 AI에게, 판단은 사람이**
- 데이터 수집, 리서치, 시각화 초안 등 반복 작업은 AI에 위임
- 최종 시장 선정, 페르소나 설정, 가치 제안 등 판단이 필요한 단계는 사용자가 결정

---

## 3. 지속적 검증 (Continuous Validation)

### ✅ 반드시 준수해야 할 사항

**3.1 각 단계마다 "이게 맞나?" 질문하기**
- PHASE 1 완료 후: "이 시장이 정말 기회가 있는가?"
- PHASE 2 완료 후: "이 경쟁 구조가 맞는가?"
- PHASE 3 완료 후: "이 페르소나가 현실적인가?"
- PHASE 4 완료 후: "이 숫자가 타당한가?"
- PHASE 5 완료 후: "이 제안이 기존 대안보다 나은가?"

**3.2 Devil's Advocate 활용**
- 자신의 분석을 비판하는 질문을 AI에게 던지기
- 예시: "이 분석의 약점을 3가지 지적하고, 대안을 제시하세요."

**3.3 가정(Assumption) 현실성 검증**
- 모든 가정에 대해 "왜 이 가정이 타당한가?" 질문
- 리스크 시나리오: "이 가정이 틀리면 어떤 일이 발생하는가?" 작성

---

## 4. 구체성 (Specificity)

### ✅ 반드시 준수해야 할 사항

**4.1 추상적 표현 대신 구체적 수치와 예시 사용**
- ❌ "시장이 크다" → ✅ "시장 규모는 $7.71B"
- ❌ "많은 사람이 겪는 문제다" → ✅ "전체 지식 노동자의 60%가 겪는 문제"
- ❌ "20-30대 직장인" → ✅ "32세 마케팅 팀장, 주 2회 야근, 연봉 5,000만원"

**4.2 페르소나 구체성**
- 반드시: 이름, 나이, 직업, 소득, 거주 지역, 기술 활용 수준 포함
- 행동 패턴: 하루 일과, 의사결정 방식, 좌절 요인 포함

**4.3 문제 가설 구체성**
- 한 문장으로 설명 가능해야 함
- 예시: "PKM 사용자는 캡처한 정보의 40% 이상을 다시 방문하지 않아, 저장한 지식을 활용하지 못한다."

## 5. 파일 관리 규칙

### ✅ 반드시 준수해야 할 사항

**5.1 결과물은 `output/` 폴더에 단계별로 저장**
- `output/PHASE1-시장선정/`
- `output/PHASE2-시장구조분석/`
- `output/PHASE3-페르소나JTBD/`
- `output/PHASE4-기회크기/`
- `output/PHASE5-서비스제안/`

**5.2 파일 명명 규칙**
- `[단계]-[세부항목]-[날짜].md`
- 예시: `PHASE1-시장선정-2026-01-10.md`

**5.3 진행상황 업데이트**
- 각 단계 완료 시 `진행상황.md`에 기록
- 완료 여부, 주요 발견, 다음 단계 작업 포함

---

## 6. 세션 종료 후 작업 이어가기

### ✅ 반드시 준수해야 할 사항

**6.1 진행상황.md에 마지막 작업 내용 기록**
- 마지막으로 작업한 단계, 완료/미완료 상태
- 다음 작업으로 넘어갈 때 확인해야 할 항목

**6.2 프로젝트-개요.md로 빠르게 복귀**
- 프로젝트 전체 구조, 시장 요약, 기술 스택 확인
- 진행 상황 파악

**6.3 TASK.md로 세부 작업 확인**
- 현재 진행 중인 단계의 체크리스트 확인
- 완료된 항목 체크, 다음 항목으로 진행

## 7. 주의사항 및 금지사항

### ❌ 절대 하지 말아야 할 것

1. **AI가 생성한 내용을 검증 없이 그대로 사용**
2. **"혁신적인 아이디어"에만 집중하고 데이터 검증 생략**
3. **페르소나를 막연하게 설정** ("20-30대 직장인" 금지)
4. **TAM/SAM/SOM을 추측으로만 작성**
5. **프롬프트 전략 없이 AI에게 "알아서 해줘" 요청**

### ✅ 반드시 해야 할 것

1. **모든 숫자에 출처 또는 계산 로직 명시**
2. **AI 결과를 최소 2회 이상 다른 방식으로 검증**
3. **페르소나마다 구체적 상황과 감정 포함**
4. **프롬프트에 "역할, 목적, 제약, 출력 형식" 4요소 포함**
5. **최종 산출물에 핵심 프롬프트 일부 공개**

| **평가 항목** | **배점** | **체크포인트** |
|---|---|---|
| **AI 기반 시장 구조화 및 분석** | 20% | • 프롬프팅을 통한 시장 구조화(5 Forces 등) 완료<br/>• 대량 데이터의 교차 검증 완료 |
| **AI 시뮬레이션 및 고객 공감** | 20% | • 다중 페르소나 생성 완료<br/>• 상황(Context) 부여를 통한 JTBD 심층 니즈 발굴 완료 |
| **AI 논리 검증 및 기회 평가** | 20% | • 추정하기 힘든 수치(TAM/SAM/SOM)의 논리적 산출 완료<br/>• 기회 요인 정량화 완료 |
| **AI 도구 활용 및 프롬프트 전략** | 25% | • 상황별 최적 도구(검색/분석/시각화) 활용 완료<br/>• 답변 품질을 높이는 프롬프트 역량 발휘 |
| **AI 협업 산출물 통합 및 완성도** | 15% | • 분석-문제-해결의 논리적 연결 완성도 달성<br/>• AI 기반 데이터 시각화(차트 등) 구현 완료 |

## 9. 완료 체크리스트

### PHASE 1 완료 체크포인트
- [ ] 선정한 시장의 문제를 한 문장으로 설명할 수 있는가?
- [ ] 이 문제가 실제로 존재한다는 것을 어떤 데이터로 증명할 수 있는가?
- [ ] 왜 지금까지 완벽히 해결되지 않았는가?
- [ ] 이 문제를 해결하면 누가 가장 먼저 혜택을 받는가?

### PHASE 2 완료 체크포인트
- [ ] 시장의 경쟁 구조를 5 Forces 관점에서 설명할 수 있는가?
- [ ] 고객의 전체 여정(Value Chain)에서 비효율 지점을 3개 이상 식별했는가?
- [ ] 기존 대안들의 한계를 명확히 파악했는가?
- [ ] AI가 개입할 수 있는 구체적 지점을 2개 이상 발견했는가?
- [ ] 분석 결과를 다이어그램으로 시각화했는가?

### PHASE 3 완료 체크포인트
- [ ] 3~5개의 구체적이고 현실적인 페르소나를 만들었는가?
- [ ] 각 페르소나의 Context-Trigger-JTBD가 명확히 정의되었는가?
- [ ] AI 롤플레이를 통해 심층 인터뷰를 수행했는가?
- [ ] Pain Point를 심각도와 빈도로 우선순위화했는가?
- [ ] 모든 분석을 다이어그램으로 통합했는가?
- [ ] 최소 3가지 핵심 Pain Point를 명확히 식별했는가?

### PHASE 4 완료 체크포인트
- [ ] TAM → SAM → SOM 추정 과정이 명확한가?
- [ ] 모든 수치에 출처 또는 계산 로직이 명시되어 있는가?
- [ ] 가정(Assumption)이 현실적인가?
- [ ] AI를 활용하여 논리적 타당성을 검증했는가?

### PHASE 5 완료 체크포인트
- [ ] 핵심 가치 제안이 10초 안에 설명 가능한가?
- [ ] AI 적용 포인트가 명확하고 현실적인가?
- [ ] 서비스 구조가 이해하기 쉽게 시각화되었는가?
- [ ] 최종 산출물이 논리적으로 연결되었는가?

## 10. 비상시 복구 규칙

**AI 결과가 신뢰할 수 없는 경우:**
1. 다른 AI 도구/모델로 동일한 작업 수행
2. 사람이 직접 수동 리서치 수행
3. 두 결과를 비교하여 격차 분석

**데이터 출처가 불명확한 경우:**
1. AI에게 "출처를 명시하세요" 추가 요청
2. 사람이 직접 공식 통계/리포트 검색
3. 출처가 확인된 경우에만 사용
